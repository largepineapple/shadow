# 需求与验收

用户为内容运营与审核团队。输入素材 ID、平台、带 offset 的发布时间、hard/soft 要求、时区、是否允许替代建议、外部明确确认的替代时间。输入对象只允许 models.py 中声明的字段。

流程：读取→确定性规则审核→缺失主动补查→查询原时段/已确认时段→模型决定保存、替代或结束→服务端核验→输出每素材结果。

六项必须验收：正常合法草稿；缺失资料不能通过；规则给出 ID 与风险并阻断/待复核；冲突建议但不擅改 hard 要求；重复请求一份草稿；保存失败准确暴露。扩展验收还包括确认后保存、预算限制、候选再占用、请求内容冲突。

成功标准包括真实模型循环及不同观察的动态动作。当前离线验证不能替代这些标准。非目标为真实发布、Web UI、鉴权、RAG、多 Agent。所有输出 published=false，completed 仅指草稿操作完成。
